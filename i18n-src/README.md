# Kastrava i18n pipeline

20 shipped languages, infrastructure for 100+.

## Shipped languages (curated, hand/model-translated)

`en, hi, ru, ja, ko, zh, ar, de, fr, es, pt, tr, vi, id, th, uk, it, pl, nl, bn`

| surface | mechanism | files |
|---|---|---|
| Website (7 public pages) | `site/wl.js` runtime: `data-wl*` spans + `WEBSTR`/`WEBSTR_X` dicts; switcher, geo auto-detect, RTL for `ar` | `site/wl.js`, `site/lang/<code>.js`, wrapped markup in `site/{index,store,privacy,terms,refunds,contact,authors}.html` |
| Desktop (Electron) | `STR` dict in `src/browser.html` (en/ru inline) + `t()`/`applyLang()`; other locales fetched from `locales/<code>.json` (webpack copies `static/` → `dist/`, served over `kastrava://`) | `static/locales/<code>.json`, `LANG_LIST` + `loadLocale()` in `src/browser.html` |
| Android | standard resources: `values-<dir>/strings.xml`, per-app locale via `LocaleHelper` + `locale_config.xml` (Android 13+ system picker) | `android/app/src/main/res/values-<dir>/strings.xml`, `LocaleHelper.LANGS`, `res/xml/locale_config.xml` |

Language choice priority on the site: **manual choice (localStorage
`kas-weblang`) → visitor IP country (`nexufog.pp.ua/api/geo`, cached per
session in `sessionStorage`) → browser language (`navigator.languages`) →
en**. The app languages are chosen in-app (Settings → Language); Android
also exposes them in system Settings → App language (13+).

## Sources

- `site.en.json` — 419 flat website keys (generated by `gen_site.py`,
  includes index/store inline keys, `cat_*`, `apkr_note`)
- `site.ru-prefill.json` — approved Russian for the 135 keys that already
  lived inline on index/store (reused verbatim, never re-translated)
- `desktop.en.json` — 130 desktop UI keys (from the `STR` dict)
- `android.en.json` — 246 Android strings `{name: {xml, formatted}}`

## Generator + patch scripts

- `gen_site.py` — wraps plain pages' text nodes with `<span data-wl="key">`
  (position-splicing: raw HTML outside splice points stays byte-identical;
  verified by roundtrip), extracts merged translator source → `site.en.json`
- `patch_site.py` — one-time page surgery: adds `<script src="/wl.js">`,
  replaces index/store's old inline EN/RU-only i18n block with the shared
  runtime hooks, adds `apkr_note`/`cat_*` keys

## Translation

- `AGENT.md` — per-language agent brief (outputs, quality rules, validation
  snippets). One agent per language, writing `site/lang/<code>.js`,
  `static/locales/<code>.json`, `android/.../values-<dir>/strings.xml`.
- `validate.py` — fleet-wide gate: key parity per surface, HTML tag parity
  (site), placeholder parity `%1$s…` (Android), XML/JSON/JS parse, wiring
  sanity (`wl.js` includes, `locale_config.xml` completeness). Run before
  every commit.

## Extending to the remaining ~85 locales

`batchfill.py` — run from an **unblocked network** (Google endpoints are
IP-blocked from some networks):

```bash
python3 i18n-src/batchfill.py list     # candidate locales not yet filled
python3 i18n-src/batchfill.py run fr-FQ # fill specific codes
python3 i18n-src/batchfill.py all       # fill everything missing
python3 i18n-src/batchfill.py check     # re-validate everything filled
```

Backends: `gtx` (Google Translate, no key, default) or `openai`
(`OPENAI_API_KEY`, batched). Placeholders, HTML tags, entities, URLs and
brand terms are **masked out of MT entirely** (split → translate free text →
reassemble byte-exact) and everything is cached in `batch-cache.jsonl`.
It prints the one-line wiring checklist (LANG_LIST / WL_LANGS / LANGS /
locale_config) after each run; `validate.py` then confirms.

## Release checklist for a new language

1. `python3 i18n-src/validate.py` green
2. `npm run build:dev` (desktop) — copies `static/locales/*`
3. Gradle build picks up `values-<dir>` automatically
4. Wire the picker lists (printed by batchfill, or edit by hand)
5. Deploy `site/wl.js`, `site/lang/*`, changed pages via scp
